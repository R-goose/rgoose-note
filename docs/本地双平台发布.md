# Windows 自动发布与 macOS 本地安装

推送版本标签后，GitHub Actions 会在本机的 `rgoose-note-release` 自托管 Runner 上一次
构建并发布 Windows x64 更新包。工作流直接使用 GitHub 已保存的 `GITEE_TOKEN` Secret，
无需在本地终端再保存令牌。macOS 不再上传到 Release；在这台 Mac 本机构建并安装即可。

如需手动发布 Windows，也可以在 macOS 开发机执行：

```bash
npm run electron:publish:gitee:win
```

该命令只构建 Windows x64 的 `.exe`，并将它和 `latest.yml`、`.blockmap` 上传到 Gitee 的
`latest` Release。发布脚本只会替换旧 Windows 文件，不会删除已经存在的 macOS 附件。

在本机制作并安装 macOS 包时执行：

```bash
npm run electron:build
```

该命令只在本地生成当前 Mac 架构的 `.dmg`；不生成 ZIP、更新清单或 macOS 自动更新文件，也不访问 Gitee。

## 发布前提

- Electron Builder 会自动下载所需的 Wine 兼容层来生成 Windows NSIS 安装器；无需自行安装
  Homebrew Wine（当前 Homebrew 的 Wine cask 已因 Gatekeeper 校验问题被禁用）。
- 手动执行命令时才需要在安全终端中配置 `GITEE_TOKEN`；令牌只用于上传，不能提交到代码、日志或截图中。
- 发布后必须在 Windows 实机安装并启动一次，确认原生 SQLite 模块可用。

发布工作流仅由这台 Mac 的专用 Runner 执行，避免 GitHub Hosted Runner 直接上传 Gitee 时出现跨网大文件失败。
