### P0：安全与数据边界

#### S0.1 AI 回复安全渲染

- [x] AI 回复进入 `v-html` 前统一进行 HTML 转义；仅由本地渲染器生成固定展示标签。
- [x] 仅生成 Markdown 所需的 `div`、`strong`、`code`、`pre`、`br` 标签，不接受模型返回的属性、脚本、框架或 URL。
- [x] 代码块、行内代码、标题、列表、加粗及普通文本使用同一条安全渲染链路。
- [x] 已增加恶意回复回归用例，覆盖 `<script>`、`onerror`、`javascript:` URL、SVG 事件，以及正常中文 Markdown/代码块。
- [~] 仍需在打包版 UI 冒烟中人工确认长回复、错误消息与复杂嵌套 Markdown 的视觉展示。

**涉及范围**：`src/components/AIFloatingButton.vue`、Markdown 安全工具、打包版 UI 测试。

**验收标准**：不可信 AI 文本只能作为文本或白名单 Markdown 显示，不能执行脚本、触发事件处理器或调用 `window.electronAPI`。

#### S0.2 Electron IPC 最小权限

- [~] 通用入口已增加静态通道白名单，renderer 不能再构造未登记的 IPC 通道；为避免一次性破坏现有 REST→IPC 路由，尚未拆成每个资源的独立方法。
- [ ] preload 改为明确的业务方法白名单，例如 `notes.list`、`notes.create`、`images.save`。
- [ ] 主进程对参数类型、长度、枚举值和 ID 格式进行校验，不仅依赖前端 UI。
- [ ] 主窗口和导出窗口分别配置最小权限，导出窗口不暴露无关的写入、删除和设置能力。
- [ ] 在不破坏现有功能的前提下评估启用 Electron renderer sandbox。

**涉及范围**：`electron/preload.js`、`electron/main.js`、`src/api/*`、导出窗口。

**验收标准**：renderer 不能构造任意 IPC 通道；每个可调用方法都有明确参数契约和主进程校验。

#### S0.3 文件路径边界与删除保护

- [~] 图片读取、解析、删除与备份打开/删除已统一使用 `path.resolve()`；其余写入与导出接口待下一轮收敛。
- [x] 上述最终路径必须位于指定图片或备份目录内，否则拒绝操作。
- [x] 上述接口拒绝 `..`、绝对路径、驱动器路径、UNC 路径和符号链接文件。
- [ ] 删除图片优先接受数据库登记的资源 ID，由主进程解析真实路径，不直接接受任意相对路径。
- [x] 备份打开、删除改为严格备份名和目录边界双重校验，不再只依赖文件名前缀。
- [ ] 增加目录穿越回归测试，保证工作区、用户目录和应用安装目录外的文件不可读写或删除。

**涉及范围**：`electron/main.js`、`electron/backend/service/imageService.js`、备份服务。

**验收标准**：所有文件接口均无法越过各自允许目录，失败时返回明确错误且不产生部分写入。

#### S0.4 AI 凭据安全存储

- [x] 桌面端不再将完整 API Key 明文保存在 localStorage；Web 运行模式保留原有浏览器存储逻辑。
- [x] 使用 Electron `safeStorage` 加密保存 Key；系统安全存储不可用时拒绝降级为明文保存。
- [x] AI 请求由主进程通过固定智谱 HTTPS 端点发起，完整 Key 不返回 renderer。
- [x] 设置页只显示“已安全保存”，支持输入新 Key 替换与一键清除。

- [~] 已避免在新增日志和 IPC 返回中携带完整 Key；仍需在打包版 DevTools、导出与截图流程做最终人工检查。

**涉及范围**：`src/views/SettingsView.vue`、`src/components/AIFloatingButton.vue`、`electron/preload.js`、主进程凭据服务。

**验收标准**：开发者工具和 localStorage 中无法读取完整 API Key；旧用户升级后配置仍可用。

#### S0.5 Electron 页面安全策略

- [ ] 为生产页面配置严格 Content Security Policy。
- [ ] 限制脚本、样式、图片、字体和网络请求来源；开发模式与生产模式使用不同策略。
- [ ] 检查外部字体依赖，优先改成本地字体或为离线失败提供完整降级。

## 一、优化建议（针对现有功能）

### 存储可靠性（高优先级）

- [x] **防丢数据**：`saveToStore` 用 `JSON.parse(JSON.stringify())` 深拷贝开销大；localStorage 超限 `QuotaExceededError` 仅打日志会**静默丢数据**，应捕获并提示导出备份 ✅ v1.3.2
- [x] **写盘前回读**：`doPersist` 每次都 `loadFromStore()` 全量读，数据量大后 IO 开销显著，建议内存维护已持久化快照 ✅ v1.3.3
- [ ] **缺版本快照**：无定时自动备份，误删难恢复，建议每次 `doPersist` 成功后保留最近 N 份轮转快照
- [ ] **单文件存储上限**：notes/folders/plans/tags 全塞 `rgoose_note_data`，localStorage 上限约 5–10MB，考虑按笔记 ID 分片或拆分多 key

### 已知 Bug

- [x] **`reminderInterval` 泄漏**：`src/stores/plan.js:168` 的 `setInterval` 从未 `clearInterval`，清缓存后仍跑空检测，应提供 `dispose()` 方法 ✅ v1.3.2
- [x] **`remindedSet` 刷新丢失**：到期前 5 分钟内反复刷新会重复触发提醒，应持久化到 localStorage 或 plan 对象的 `lastRemindedAt` 字段 ✅ v1.3.2
- [x] **通知权限突兀**：`init()` 自动弹原生授权，应改为创建首个带提醒计划时再询问，或挪到设置页 ✅ v1.3.2
- [x] **时间基准不一致**：`overduePlans` 用 `Date.now()`，`todayPlans` 用 `new Date()` 构造边界，且不响应跨午夜，应统一时间基准并每分钟刷新 `now` ref ✅ v1.3.2

### 编辑器体验

- [ ] **统一 popover 管理**：工具栏 popover 靠 `@click.stop` 管理，多菜单易并存，应抽 `useClickOutside` 组合式函数
- [ ] **大图粘贴限制**：粘贴大图无压缩限制，imageStore 易膨胀，应做尺寸/体积阈值检测，超限压缩或提示
- [ ] **搜索范围扩展**：`searchNotes` 仅覆盖 title + blocks content，未含 tags/folders/plans，且无高亮定位

### 命令面板

- [x] **性能优化**：`commands` 每次 query 变化都重建全部笔记映射，笔记多时卡顿，应抽到非 query 依赖的 computed ✅ v1.3.3
- [ ] **匹配增强**：仅 `includes` 子串匹配，无模糊/拼音/最近使用加权

## 二、新功能建议

### 1. 笔记版本历史（Time Travel）
- **价值**：画布式笔记误删/误改成本极高（拖错 block、误删连线难恢复），当前仅软删除无时间线回溯
- **思路**：`doPersist` 时按笔记维度存轻量快照（blocks/connections diff 或每 N 次修改一份）；编辑器侧栏时间轴预览并"恢复到此版本"；限制保留数（如每篇 20 份）

### 2. 笔记模板系统
- **价值**：用户重复创建相似结构画布（周计划、读书笔记模板），每次手动搭
- **思路**：noteStore 增加 `templates` 数组（结构同 note，标记 `isTemplate: true`）；新建笔记"从模板创建"复制 blocks/connections；预置官方模板

### 3. 计划与笔记 block 的双向联动
- **价值**：画布任务块与全局 plan store 是两套体系，用户易割裂
- **思路**：画布任务块可"提升为计划"，写入 plan store 保留 `blockId` 反向引用；画布显示关联计划状态，PlansView 反向跳转高亮

### 4. 日历视图（计划页）
- **价值**：PlansView 当前只有逾期/今天/全部/已完成四段列表，缺乏时间维度概览
- **思路**：PlansView 顶部增加月历视图切换，按 `dueDate` 渲染到日期格子；支持拖拽改期；格子内显示优先级色点；复用 `DateTimePicker`

### 5. 全局快速捕获（Quick Capture）
- **价值**：灵感来时不想先进文件夹→新建→加 block
- **思路**：全局快捷键（如 `Ctrl+Shift+Space`）唤起轻量输入框（复用 CommandPalette 样式）；回车创建笔记（首行标题、内容成 text block）或计划（`!` 前缀识别）；落地默认文件夹

### 6. 笔记间双向链接与关系图
- **价值**：已有"引用笔记"功能但关系不可视，画布式应用天然适合知识图谱
- **思路**：note 增加 `links: [{toNoteId, fromBlockId}]`，引用时维护；新增 `/graph` 路由用力导向图展示，节点大小按引用数/更新时间；可作为 Dashboard 面板

### 7. 数据加密与多设备同步基础
- **价值**：当前明文存储，涉及隐私笔记无保护
- **思路**：设置页增加"应用密码"与"加密存储"；Web Crypto API (AES-GCM) 加密 content 后序列化；为未来多端同步预留 `mergeData` 冲突解决路径

### 8. 画布块的多选与批量操作
- **价值**：逐个拖拽/删除/改色效率低
- **思路**：框选（空白拖拽画矩形）多选 blocks；多选态支持批量改色/对齐/成组移动/删除/连线；noteStore 增加 `updateBlocks(noteId, ids[], updates)` 批量接口

### 9. 计划的子任务与依赖
- **价值**：plan 模型扁平无父子无依赖，复杂计划难拆解
- **思路**：plan 增加 `parentId` 与 `dependsOn: [planId]`；PlansView 支持折叠展开子任务；父任务完成校验子任务全完成；依赖未完成阻止标完成并提示

### 10. 仪表盘的"今日聚焦"与完成趋势
- **价值**：Dashboard 偏静态统计，缺乏行动指引和趋势感
- **思路**：顶部"今日聚焦"卡聚合今日到期计划 + 最近编辑 3 篇笔记；近 7/14 天任务完成折线图（plan 补 `completedAt` 字段）；"连续打卡天数"等激励指标
